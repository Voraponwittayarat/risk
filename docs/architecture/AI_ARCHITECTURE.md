# Future AI Architecture Layer

The modernized RiskHRMS is designed to support clinical decision support and predictive analytics via AI, without compromising the stability of core reporting.

## 1. Event-Driven AI Bus
- **Trigger**: When a new incident is logged via the REST API, an event is published to an asynchronous message broker (e.g., Redis PubSub or RabbitMQ).
- **Consumption**: An isolated AI microservice (Python/FastAPI) consumes the incident details, completely disjoint from the main transaction path, ensuring no latency is added to the user's reporting experience.

## 2. NLP Triage & Semantic Search
- **Function**: The AI service analyzes the narrative description (`detail`) using a healthcare-tuned LLM or NLP model.
- **Goal 1 (Severity Suggestion)**: Highlights if the narrative implies a higher severity than the user selected (e.g., user selects 'C' but mentions "patient fell and fractured hip").
- **Goal 2 (Repeat Detection)**: Performs vector similarity search against past incidents to alert management if this is a recurring systemic issue (Surveillance module).

## 3. Data Isolation and Safety
- **Read-Only Access**: AI models will only possess read-access to the primary database replica.
- **Advisory Output**: Output from AI (suggestions, confidence scores) is stored in a separate schema (e.g., `ai_metadata`). AI never overwrites human-entered clinical data.
- **Human-in-the-Loop**: Dashboard alerts generated by AI must be explicitly acknowledged or dismissed by a unit manager.
