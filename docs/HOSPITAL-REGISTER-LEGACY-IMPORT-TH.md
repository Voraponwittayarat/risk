## การทำงาน

1. RM ที่มี rmScope=hospital หรือ Admin เปิด Reports แล้วกด **นำเข้าทะเบียนเดิม**
2. เลือกไฟล์ JSON ที่จัดเตรียม รูปแบบ `riskhrms-hospital-register-v1` (สูงสุด 90 KB ต่อไฟล์และ 100 เรื่อง)
3. กด **ตรวจตัวอย่างก่อนนำเข้า** แสดงชื่อ คะแนน Owner วันนัด และรายการซ้ำ
4. กดนำเข้า ระบบตรวจข้อมูลและ fingerprint ซ้ำใน transaction แบบ Serializable ก่อนเขียน พร้อม workflow audit หาก preview เปลี่ยนจะให้ตรวจใหม่
5. เปิดทะเบียนโรงพยาบาลเพื่อตรวจจำนวน รายละเอียด และมาตรการ คงข้อมูลเดิมของรายการซ้ำไว้ทั้งหมด

API ใช้ JWT: `POST /risk-analysis/import-legacy/preview` และ `/commit` ตัวนำเข้าทำงานผ่านสิทธิ์บัญชีเว็บ ไม่แก้ฐานข้อมูลด้วย SSH

## การรักษาความหมายเดิม

- เก็บชื่อความเสี่ยงเดิมด้วยรหัส LEGACY-HOSP ที่สร้างจาก file ID, sheet และชื่อเรื่อง ไม่มี NRLS ปลอม ไม่ยกเว้นกติกา NRLS ของการสร้างรายการใหม่ตามปกติ
- เก็บคำอธิบาย กระบวนการ วัตถุประสงค์ วันที่เพิ่ม แหล่งที่มา ผลทบทวน และสถานะต้นฉบับในรายละเอียด พร้อม SHA-256 และแถวอ้างอิง
- คอลัมน์ป้องกันและถ่ายโอนเดิมรวมอยู่ช่องเดียว จึงเก็บข้อความร่วมไว้ใน risk_prevention ไม่แยกส่วนด้วยการเดา
- L/C เป็นคะแนนตั้งต้นจากต้นฉบับ คำนวณสีตาม matrix ของระบบ ไม่สร้างคะแนนคงเหลือหรือประวัติทบทวนที่ประเมินขึ้นใหม่
- last_reviewed_date เก็บวันเดิม ปี ค.ศ.2024 คือ พ.ศ.2567; ข้อความ 20/2/24 อ่านเป็น 2024-02-20 ตามบริบทปีของต้นฉบับ
- next_review_date คำนวณจากวันทบทวนเดิม + รอบ 3 หรือ 6 เดือน ไม่เลื่อนตามวันนำเข้า ดังนั้นอาจเกินกำหนดอยู่แล้ว
- เชื่อม Risk Owner กับ member/account เฉพาะชื่อที่ตรงแบบแน่นอนและไม่กำกวม ถ้าไม่พบหรือซ้ำเก็บชื่อเดิมไว้โดยไม่มอบหมายบัญชีผิดคน
- รายการยังไม่เชื่อม NRLS แสดงป้ายในทะเบียน ปุ่มจัดประเภทเปิดแบบแก้ไข ก่อนนับ Incident/ทบทวนตามกติกาเดิมของระบบ ข้อมูลเดิมยังคงอยู่ในรายละเอียดหากจัดประเภทแล้วชื่อ master ต่างจากต้นฉบับ
- ไม่สร้าง Incident หรือ CAPA ใหม่จากข้อความแผนเดิม การเปิดมาตรการพร้อม Owner/deadline ต้องทบทวนเพิ่มเติม
