# รอบแรก: งานที่ฉันต้องทำต่อ

ปรับหน้าแรกจากข้อมูลเดิม โดยไม่เพิ่มช่องกรอก ฐานข้อมูล หรือสิทธิ์ดำเนินการ

- `DashboardTasks.tsx`: แยกรายงานของฉันที่ต้องแก้ไขออกจากคิวในขอบเขตดูแล แสดงขอบเขตและช่วงข้อมูล รองรับโหลดผิดพลาดและลองใหม่
- `Dashboard.tsx`: ส่งจำนวนรายงานส่วนตัวจากข้อมูลที่โหลดอยู่แล้ว ไม่เพิ่ม API สำหรับรายงานส่วนตัว
- `MyReportedIncidents.tsx`: รับปีงบประมาณและตัวกรองจากลิงก์หน้าแรก เพื่อเปิดรายการที่ตรงกับยอด
- เจ้าหน้าที่เห็นงานแก้ไขของตน หัวหน้าและ RM เห็นคิวดูแลเพิ่ม ผู้ดูแลระบบเห็นลิงก์เปิดดูโดยไม่อ้างว่ามีสิทธิ์ตัดสินใจทุกเรื่อง
- ลิงก์งานทีมและ CAPA ใช้เงื่อนไขสิทธิ์เดียวกับหน้าปลายทาง ไม่เพิ่มสิทธิ์จากหน้าแรก
- รายงานส่วนตัวนับเฉพาะปีงบประมาณที่เลือก คิวในขอบเขตดูแลนับทุกปีตาม API เดิม ไม่อ้างว่าเป็นรายการงานทั้งหมดหรือเป็นลำดับความเร่งด่วนทางคลินิก

การตรวจสอบ: build frontend/backend, ชุด unit tests CSV และสัญญาณการเรียนรู้,
browser smoke ด้วยข้อมูลจำลอง รวมบทบาท staff/team/head/hospital RM/admin,
ลิงก์ตัวกรอง การโหลดผิดพลาดและลองใหม่ และหน้าจอมือถือ

สถานะ release: ผู้ดูแลสั่งให้ push GitHub main ไว้ก่อนขณะ Server ยังใช้ไม่ได้
ยังไม่ได้ยืนยัน backup, running commit หรือ health บน production สำหรับรอบนี้
เมื่อ Server กลับมา ให้ตรวจผล Auto Deploy ซึ่งต้องผ่าน updater สำรองข้อมูลและ
ตรวจ checksum ก่อนอัปเดต จากนั้นตรวจ health, login, รายการ incident แบบอ่านอย่างเดียว
และหน้าแรกตามบทบาท ห้ามแก้ source บน Server โดยตรง
