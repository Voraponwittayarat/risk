# คู่มือการตั้งค่าระบบอัปโหลดรูปภาพและการเชื่อมโยงข้อมูลเก่า (Incident Image Upload Setup & Migration Guide)

คู่มือฉบับนี้อธิบายแนวคิดการจัดเก็บ รูปแบบฐานข้อมูล และวิธีตั้งค่าตัวแปรสิ่งแวดล้อม (Environment Variables) เพื่อเชื่อมโยงรูปภาพของระบบเดิม (Yii 2 PHP) เข้ากับระบบใหม่ (Vite + NestJS) ให้ทำงานร่วมกันได้อย่างสมบูรณ์

---

## 1. แนวคิดและรูปแบบการจัดเก็บข้อมูล (Storage Architecture)

- **ไฟล์รูปภาพจริง (Physical Files)**: จะถูกจัดเก็บรวมไว้ที่ตำแหน่งเดียวกันกับโฟลเดอร์ภาพของระบบเดิม ซึ่งปกติอยู่ที่:
  `frontend_old/web/riskimage/`
- **การบันทึกฐานข้อมูล (Database Values)**: ในฟิลด์ `image` ของตาราง `riskregister` และตาราง `risk` จะบันทึกเฉพาะ **"รายชื่อไฟล์แบบคอมมาคั่น"** (Comma-separated filenames) โดยไม่มีชื่อพาธ เช่น:
  `5db969c3a37213459abdc5e5df.png,d83e29f37c35272a8385.jpg`

ด้วยรูปแบบนี้ จะทำให้:
1. ข้อมูลในระบบเดิมที่เคยอัปโหลดไว้ สามารถดึงมาแสดงผลบนเว็บใหม่ได้ทันที
2. รูปที่ผู้ใช้อัปโหลดผ่านเว็บใหม่ จะไปปรากฏและแสดงผลบนเว็บเดิมได้เช่นกัน

---

## 2. การตั้งค่าบนสภาพแวดล้อมต่าง ๆ (Environment Configuration)

ระบบใช้ตัวแปรสิ่งแวดล้อมชื่อ **`UPLOAD_DIR`** ในไฟล์ `.env` ของฝั่ง Backend (`backend/.env`) เพื่อกำหนดโฟลเดอร์ปลายทางที่ใช้เก็บภาพ

### A. สภาพแวดล้อมการพัฒนาในเครื่อง (Local Development)
ระบุพาธแบบสัมพัทธ์ (Relative path) ชี้ไปยังโฟลเดอร์เว็บเก่า:
```env
# backend/.env
UPLOAD_DIR="../frontend_old/web/riskimage"
```
*(หากโฟลเดอร์นี้ไม่มีอยู่จริง ระบบจะทำการสร้างโฟลเดอร์ขึ้นมาให้โดยอัตโนมัติ)*

### B. สภาพแวดล้อมการใช้งานจริง (Production Deployment)
เมื่อนำระบบขึ้นโฮสต์จริง (Production) ให้เปลี่ยนค่า `UPLOAD_DIR` ชี้ไปยังพาธแบบสัมบูรณ์ (Absolute path) ของไดเรกทอรีที่จัดเก็บไฟล์รูปภาพจริงบนเซิร์ฟเวอร์ เช่น:
```env
# backend/.env (ตัวอย่าง Linux Server)
UPLOAD_DIR="/var/www/html/riskHRMS/frontend_old/web/riskimage"
```

## 3. ขั้นตอนการตั้งค่าและย้ายระบบ (Migration & Deployment Steps)

เมื่อต้องการเชื่อมฐานข้อมูลจริงและนำเว็บใหม่ขึ้นใช้งาน ให้ปฏิบัติตามขั้นตอนต่อไปนี้:

### ขั้นตอนที่ 1: กำหนดสิทธิ์ไดเรกทอรี (Directory Permissions)
บนเซิร์ฟเวอร์จริง ระบบ NestJS (Backend) จำเป็นต้องมีสิทธิ์ในการเขียนไฟล์ลงในโฟลเดอร์รูปภาพ ให้รันคำสั่งกำหนดสิทธิ์ (ยกตัวอย่างบนระบบ Linux):
```bash
# กำหนดเจ้าของโฟลเดอร์ให้เป็นของผู้ใช้ที่รันเว็บ (เช่น www-data หรือ node)
chown -R www-data:www-data /var/www/html/riskHRMS/frontend_old/web/riskimage

# กำหนดสิทธิ์ให้อ่านและเขียนไฟล์ได้ (775 หรือ 755 ตามนโยบายความปลอดภัย)
chmod -R 775 /var/www/html/riskHRMS/frontend_old/web/riskimage
```

### ขั้นตอนที่ 2: ตั้งค่าตัวแปรสิ่งแวดล้อมในเว็บเซิร์ฟเวอร์
1. แก้ไขไฟล์ `.env` ของ `backend` ชี้ `UPLOAD_DIR` ไปยังโฟลเดอร์ที่เก็บรูปภาพจริง
2. ตรวจสอบว่า `DATABASE_URL` ชี้ไปยังฐานข้อมูลจริงของระบบเรียบร้อยแล้ว

### ขั้นตอนที่ 3: ตรวจสอบการทำ Reverse Proxy (ถ้ามี)
เว็บใหม่เข้าถึงภาพผ่าน URL `/uploads/...` ซึ่งในเครื่องพัฒนาเราจำลองผ่าน Vite Proxy ไปยังพอร์ต `3000` แล้ว
หากคุณใช้ Nginx เป็นเว็บเซิร์ฟเวอร์ในระบบจริง อย่าลืมตั้งค่า Proxy ให้ชี้ `/uploads` ไปที่ NestJS หรือให้ Nginx บริการไฟล์ตรงจากโฟลเดอร์ภาพเลยก็ได้ ตัวอย่างคอนฟิก Nginx:
```nginx
location /uploads/ {
    alias /var/www/html/riskHRMS/frontend_old/web/riskimage/;
    expires 30d;
    add_header Cache-Control "public, no-transform";
}
```

## 4. สรุปฟังก์ชันการตรวจสอบฝั่งไคลเอนต์ (Client-Side Validations)

หน้ารายงานความเสี่ยงมีระบบป้องกันที่ฝั่ง Frontend ดังนี้:
- **จำนวนไฟล์สูงสุด**: 3 รูป (หากเลือกครบ 3 รูป ปุ่มอัปโหลดจะถูกปิดใช้งาน)
- **ขนาดไฟล์สูงสุด**: ไม่เกิน 3.00 MB ต่อรูป (ตรวจสอบผ่าน JavaScript `file.size` ก่อนทำคำร้องส่ง)
- **ประเภทไฟล์**: รองรับเฉพาะไฟล์รูปภาพหลักเท่านั้น (`image/jpeg`, `image/jpg`, `image/png`, `image/webp`)
- **การแจ้งเตือน**: หากตรวจพบไฟล์ที่ขนาดเกินหรือประเภทไม่ถูกต้อง ระบบจะแสดงแบนเนอร์แจ้งเตือนสีแดง และไม่นำไฟล์นั้นเข้าสู่คิวอัปโหลด
